# 外观只依赖宿主设计 token，且 token 名由测试验证存在

面板的颜色取自宿主的 `--dsw-alias-*` 变量（唯一例外是热力图五档色阶，见文末代价），不再自带深色专用兜底值；引用的 token 名由 `test/appearance.test.js` 对照宿主主题包验证存在。这条约束不显然，因为它守护的缺陷**在代码里完全看不出来**。

宿主主题包给出两套值：`body{...}` 是浅色、`body[data-ds-dark-theme]{...}` 是深色，各 93 个 alias token；而宿主的默认外观是**跟随系统**（`DEFAULT_PREFERENCE = "system"`，并持有 `prefers-color-scheme: dark` 媒体查询），所以「用户没配过主题」≠ 深色——绝大多数人是浅色。

此前面板引用了两个宿主**根本不存在**的 token：`--dsw-alias-text-primary` 与 `--dsw-alias-border-1`（实测定义数为 0；实际存在的是 `--dsw-alias-label-primary` 与 `--dsw-alias-border-l1/l2/l3`）。CSS 的 `var()` 找不到变量时**不报错、不警告**，静默取兜底值——而兜底值是为深色写死的：正文 `#e6e6e6`、边框 `rgba(255,255,255,.08~.14)`。于是在浅色系统上正文只有 **1.25:1**（WCAG AA 需 4.5:1），白底上的白色边框合成后**恰好等于 `#ffffff`**，卡片与分隔线整片消失。

**没有测试能看见这些**，原因值得写清楚：测试**确实**断言过 token 名（基线 `test/client.test.js` 有 `/var\(--dsw-alias-bg-layer-2/`），但断言的是渲染元素上的 **inline style**；那两个错误 token 只出现在 `const CSS` 模板字符串里（基线 8 处，全在 96–131 行的样式表段），而它**从不导出**——`exports` 只暴露 `apply`/`inject`/`Badge`/`Panel`/`Heatmap`/`fmtTokens`。所以测试面够到了 inline style、够不到样式表，写在 CSS 里的错误 token 名完全不可见。

**决定**：① 只用宿主 `--dsw-alias-*`，兜底值一律改为中性的 `currentColor`，不再写深色专用 fallback；② token 名由测试对着宿主主题包断言存在，把「名字写错」从静默降级变成失败。浅色下 `bg-layer-1/2/3` **三者同为 `#fff`**（深色才是 `#232324 / #2c2c2e / #353638`），所以层次**不能**靠底色表达，改由边框 token 承担——卡片、面板、未选中页签、进度条槽都显式带边框。热力图色阶不用 `color-mix()`：它需要较新浏览器且没有 `@supports` 回退，老浏览器上五档塌成同一色，且混的是 `brand-primary`（宿主里是墨色/对比色，不是色相），主题间色相还会反转；改用静态色 + `body[data-ds-dark-theme]` 分主题给出，真实格子与图例共用同一条规则。

热力图分档也从「除以全窗口单日峰值」的线性阈值改成**活跃日分位数**（P25/P50/P75，最忙的一天恒为最高档）。线性阈值会被一个异常忙碌的日子压平：以 2026-09-28 的实时语料（`$DSH_HOME/sessions`，356 个文件、15701 条记录）为例，13 个活跃日的最高日是中位数的 **40.3 倍**，旧规则落成 L1=11 / L2=0 / L3=1 / L4=1——整年看起来只有两天在干活，分位数规则落成 4/3/3/3。这些倍数与分布**不是数据的不变量，而是某一时刻语料的读数**：同一份代码在冻结快照（11695 条记录）上是 18.6 倍、旧规则 10/1/0/2，实时目录还会随会话推进继续变（本次核对期间 records 从 15608 涨到 15701）。所以这里记的是判断依据——「单日峰值会压平其余活跃日」——而不是某个倍数。

代价：新增一种视觉状态要在 CSS 与测试里各写一次（ADR-0004 排除了构建步骤，没有工具能替我们生成）；热力图色阶是插件自带的常量，宿主没有强度色阶 token，换主题时需人工核对。文字色一律取自正文墨色 token，语义色 token 只通过底色与边框表达状态——当作文字色用就会重演「琥珀字铺在琥珀底上」（2.58:1）那类低对比度。
