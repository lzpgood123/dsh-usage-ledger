# 逐帧解压多帧 zstd，而非单次解压

会话日志容器是**多帧拼接**的 Zstandard（DSH 为了能追加写入而不重压全文）。Node 的 `zstdDecompressSync` 只解第一帧，把整个文件丢进去只会得到一个头行。因此先扫描帧边界，再逐帧解压。

这是一个**看起来像冗余、实际不能被"简化"掉的刻意设计**：任何把它改回单次解压的改动，都会静默丢掉除首帧外的全部数据，而且不报错。

实测 60 个会话文件，单次解压**全部**丢数据（平均每文件 419.73 帧）；最严重一例单次解压只剩 2 行，逐帧解压有 7628 行，丢失约 420 万字符。

单帧损坏也不该让整个会话消失，所以解压失败的帧按跳过处理，其余帧照常统计。
